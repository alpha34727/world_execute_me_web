## 逐鏡頭

**properly（f10976、f11076）**
- 概念很準：repo 頂層檔名排成一列，spark 一個一個往下讀，停在 `love.md` 該在的位置，左側 `● Read(love.md) ⎿ File does not exist.` 是真結果。有幽默，也有「me 想學愛卻找不到資料」的敘事。
- 構圖（3）：f10976（鏡頭一開始）只有 5 個名字，集中在 x≈805–980、y≈600–1000，右上整片空；最下一個 `CLAUDE.md`（y≈997）緊貼字幕框上緣（框頂 y≈920，水平上不重疊，但視覺上很擠）。f11076 列表間距 ≈ 115 px，名字像是漂浮的孤字，而不是一份清單。
- 風格（4）：`love.md` 的「空格」本應是虛線框（`dash: 6, gap: 5`），但 f11076 的 1080p 畫面是一個實線細框，還略微歪斜（透視），虛線感完全沒出來，讀不出「這裡缺一個檔案」。`File does not exist.` 是 20 px 的暗灰字（約 #5e5d59 對 #1c1c1b），對比偏低，這是全章唯一重要的一句字，卻最難讀（建議 1）。

**love1（f11137）**

**question（f11186）**

## 擋關（blocker）

1. **algebraic：心形曲線有缺口（`src/ch/love/curves.js:24`，`heartSegments`）**。f11461 的曲線在左右腰側有可見的小缺口。因為場函數是三次方，過零附近太平，線性內插誤差大。請改成：
   - 把網格上的值先取 `cbrt`（`Math.cbrt(f)`，保號），再用同一個 `s = f0/(f0−f1)` 內插（cbrt 讓函數在過零處接近線性）；符號判斷不受影響。同樣處理 `heartRings` 的 `heart3` 值（那 8 個環在 f11713 邊緣也有微小抖動）。
   - 或把 N 由 160 提高到 320（成本很小，因為是 memo 一次建好）。
   - 修完要重截 `love.06` 與所有 cage 鏡頭，baseline 會變，請列入 `test/regression.exempt` 或更新 baseline。

## 建議

1. **properly**：(a) 把 `File does not exist.` 提到 `COLOR.ink2`（或 `mid gray`），並加大到 22 px（現在 20 px、暗灰）；(b) 虛線框：在 1080p 下 `dash 6 / gap 5` 看不到，改成 `dash: 14, gap: 9`、寬度 2，並讓它不要跟著透視歪（`persp` 設 0 或放在 3D 平面上對齊文字）；(c) 開場空的右上區可以放 2–3 個遠景餘燼或延長列表（在 slot 之前多放 3 個名字），讓 f10976 不再只有 5 個字。
2. **question**：加一點能量層而不改動孤寂感——例如 `embers` 的 alpha 從 0.55 提到 0.8、顏色用玫瑰／灰，再讓 `shockwave` 每拍多一圈（現在只有 q 與 q2 各一圈）。保持畫面簡潔，但避免空到像沒有渲染完。
3. **question 的 `>`**：把 `>` 改成灰色（`COLOR.dim`）或沿用游標灰，只有在「Question」那一拍才閃成玫瑰；橘色 `>` 暗示 me 正在輸入，與「沒有人在輸入」矛盾。
4. **answer**：`drawPrediction` 的 `from` 提早打開時，把 `waiting for context…` 那一行拿掉（`predict.js` 在 `!known` 時只畫 spinner），讓面板只有 `next token` 標題＋`Predicting…` 兩行。
5. **love2**：玫瑰 plane 的 `a = (j/6)·π` 會讓某一朵（j = 3，a = π/2）的 u 軸沿視線方向，投影塌成一條垂直線。請把 `a` 改成 `(j + 0.5)/6 · π`，避開 0 與 π/2；同時把玫瑰整體下移（`target` 的 y 改 −0.35）或把 `1.7` 改成 `1.5`，讓花瓣頂端離 hero 底線（y≈245）至少 60 px。
