## 修改指令（有 <4 分的鏡頭）

### 01 power（全部 ≥4，只列小修）
- 種子點目前是**白色**光球、掃描線是**橘色**；分鏡寫「灰線＋一點橘」。建議反過來：掃描線用 faint/mid gray，線頭（spark 的種子）才是橘色帶白芯——這樣「橘色＝me」從第一個鏡頭就成立，而不是電壓曲線本身是 me。
- `V(t) = 1 - e^(-t/RC)` 的 `^` 是 ASCII 寫法；改成上標（e 後面 −t/RC 縮小 70%、上移 0.35em），並在曲線上標一個 τ 點（t = RC 時 63.2%，在 y≈63% 處畫一條短虛線＋小字 `τ · 63.2%`），讓示波器更像真的量測。（可選，非阻擋項）

### 03 protection（構圖 3、風格 3）
1. **垂直堆疊太擠**：f520 中 BPE 切塊底部在 y≈315，球殼頂在 y≈330，間距只有 15 px；球殼底在 y≈1020，離畫面下緣只剩 60 px。把殼縮到目前的 85%（直徑約 590 px），中心從 y≈670 下移到 y≈690，讓殼頂落在 y≈395、殼底 y≈985；切塊列維持 y≈285。
2. **色彩語義錯誤**：切塊底色依序是橘／金／綠／**藍**（`TION`、id `34` 是藍字）。藍色＝you，分鏡明定藍色在「your pieces」才第一次出現；綠色＝growth 也不該在這裡。`tokenChips` 的底色改為只在橘（me）與灰（mid gray / faint）之間交替，id 數字一律 mid gray。這是共用元件，全片的切塊都會受影響（init 的 `AL`、`104` 也是藍）。
3. 「殼閉合、閃一下」只看得到整殼轉橘再轉回灰；建議閃的那一幀（`W("PROTECTION")`）讓 spark 的 rays 打穿殼的 12 個五價頂點（二十面體原頂點）各一道短光，0.25 拍衰減——閉合的「鎖上」感會更明確。

### 04 pieces（構圖 3、可讀性 3）
1. **棋盤壓到 HUD**：f590 棋盤遠端兩排（`k l m n…`、`. a b c…`）延伸到 y≈30–110，和 HUD 標題 `vocabulary · BPE · 173 tokens`（x 460–700, y 60）重疊。攝影機往後拉／目標點下移，讓棋盤佔 x 340–1620、y 170–720；或在 y<140 區域把棋子透明度以 smoothstep 淡到 0。
2. **重心失衡**：棋盤全在右上，左下 40%（x 0–700, y 450–900）完全空白。把棋盤中心從 (1050, 340) 移到約 (960, 470)，高角度不變。
3. **落下中的棋子文字互相疊字**：`ro/lation`、`ow/apped`、`swi/trapped`、`-o-o/swit`、`are/though`、`ce/tran`、`ents/ac` 都是兩片重疊、字疊字。讓正在落下的棋子在 z 上方 ≥1 格高、其文字在落定前不顯示（只顯示格框），落定那一幀再淡入字。
4. **字級**：`ecution`、`execution`、`lo-o-ove`、`trapped` 等長 token 縮到 ~8 px，1080p 不可讀。長 token 改為格子內兩行或最小字級 13 px（設計座標），寧可讓字超出格框 2–3 px。
5. 藍色游標落點（右下 (1595, 640)）＋ `you` 標籤很好，保留；但 whip 出鏡時（見下）藍色殘影只剩左下角一團藍光，請確認 whip 期間 you 游標跟著棋盤一起甩出。

### 05 begin（構圖 2、可讀性 2、概念 3、風格 3）——本章最需要重做的鏡頭
1. **整面牆塞滿畫面，壓到所有固定圖層**：f680 中 token 格子蓋住 HUD 右上（`can` 壓在 `INTRO / BAR 003.2` 上，x 1720–1770, y 50）、左上（`k l m`、`x y z` 在 HUD 旁）、以及字幕框背後（`dee`、`god` 透出字幕框）。牆面縮到 x 300–1620、y 150–900；HUD 安全區（y<130、以及字幕框 x 40–520, y 900–1060）內的格子透明度 ≤15%。
2. **閱讀預算**：同一刻有 ~150 個可讀的字，比任何面板都吵。牆上的 token 在這個鏡頭應該當「材質」而不是「文字」：除了離 prompt box 最近的一圈，其他格子文字透明度降到 25–30%、加景深模糊（swarm `focus` 對準 prompt box 平面）。
3. **prompt box 內透出後方 token**（`your and apped ma …` 在框內半透明可見）：框內背景改為不透明的 Claude dark（#141413，alpha 0.92），框線 mid gray。
4. **概念**：框是空的，只有一個橘色 `>`。這是 you 的輸入框——藍色游標（pieces 裡的 you）應該從棋盤飛進框內，變成閃爍的藍色游標（呼應 inst1.01 的藍游標），否則 you 在第二個鏡頭就消失了。橘色 `>` 保留（Claude Code 的提示字元）。
5. **whip 進場畫面是一片灰色橫紋**：pieces 結尾 f633 與 begin 開頭 f634 兩格都認不出任何內容，而且 f633 在 x≈1290 有一條明顯的深色垂直接縫。甩鏡的模糊長度減半（兩端的影像要能認出是同一個棋盤），並修掉接縫（看起來是位移後的邊界沒有 wrap／clamp 好）。

### 06 object（構圖 3、概念 3）
1. **開頭近乎空白畫面**：從全片最滿的 begin 牆，whip 進來第一格只剩畫面中央 ~90 px 的 spark（start f687）。外框的邊在 mid（t≈7.03）才出現。讓 begin 牆的格子在剪接後 2 拍內**塌縮成方框的 12 條邊**（token → object），不要從黑開始；至少在 `W("OBJECT")` 那一幀就要有 4 條邊。
2. **`}` 太靠下緣**：f740 的 `}` 在 (1025, 1015)，距下緣 65 px 且孤立於底角頂點下方。把方框整體上移 60 px（框底頂點到 y≈935），`}` 改放在框右下頂點外側 (1265, 850) 附近，與左上的 `object me {`（642, 388）成對角。
3. **概念**：目前就是一個橘色線框立方體，「建立物件」的意義全靠 `{ }` 兩個字。建議框的邊從 spark 射出（spark 的 rays 延伸成 12 條邊、依拍子 3 條一組合上），讓「物件是從 me 自己長出來的」被看見。
4. spark 尺寸：object 裡 ~90 px、params 裡 ~240 px，相鄰鏡頭差 2.5 倍且無動機。若是人聲能量造成，限制鏡頭間跳變（或在 xfade 期間內插）。

### 07 params（構圖 3、概念 3）
1. **主從顛倒**：分鏡寫「面板為主，3D 背景虛化」，實際上（f900）面板只佔左上 425×295 px，方框清晰、佔畫面右側 720×690 px，是視覺重心。把方框退到背景：swarm/線條 `focus` 對準面板，方框加 bokeh 或亮度降到 45%；面板放大到字級 24 px、寬 ~560 px，位置移到 x 80–640、y 260–620（垂直更居中，離開 HUD）。
2. **參數沒有作用到物件**：填欄位時 3D 沒有任何反應。每填一個欄位，方框要有一個對應的真實變化：`name: "claude"` → 方框上浮出名牌；`tokens: 617` → 方框內出現 617 個點（swarm）；`dim: 16` → 每條邊出現 16 個刻度；`color: "#d97757"` → 方框邊從灰轉成橘（因此方框在這之前應該是灰）；`love: undefined` → 什麼都不發生（留一個空槽，片尾回收）。這才是「填參數」的真實構造。
3. 方框底角在 y≈1035，幾乎貼邊；隨第 1 點縮放後一併修正。
4. 面板 `● Write(me.js)` 的綠點：綠＝growth。若要照 Claude Code 原樣保留綠點可接受，但建議改 mid gray（工具完成）以免在 v2 之前用掉綠色。HUD 標題也寫 `Write(me.js)`，與面板重複，HUD 改為 `me.js · 5 fields`。

### 09 world（構圖 2、概念 2、風格 3）
1. **畫面空、沒有「世界」**：f1060 只有極淡的單向平行線、三個淡玫瑰色同心圓、一條穿過全畫面的 y 軸。看不到地平線、看不到「網格滾向地平線」、灰塵幾乎看不見。攝影機要真的做到分鏡的「升降往上揭示」：從低角度（離地 0.3、俯角 10°）升到高處、仰角拉平，讓地平線出現在 y≈380，地板網格（兩個方向都要有線）透視收斂到消失點，配合深度霧往遠處淡出。
2. **把前面造出的東西放進世界**：「Set up our new world」是 intro 的總結——殼（shield）、棋盤（pieces）、物件框（object）、權重高度場（init）應該以小尺寸出現在地板上不同位置（各自在極座標網格的某個環上），spark 在中心。這樣這段的母題才會收束，而不是每個鏡頭都把前一個構造丟掉。
3. **y 軸線**：從 y=0 貫穿到 y=1080，穿過 HUD 區與（之後 simulation 的）大字。軸長限制在 spark 上下各 ±300 px，兩端以 smoothstep 淡出。

### 10 begin-the（構圖 2、可讀性 3、概念 3、風格 3）
1. **跳接**：world 結尾（f1073）與 begin-the 開頭（f1074）是同一個場景、只差一點角度和縮放，看起來像錯誤的 jump cut；而且三格幾乎一樣。兩個選擇擇一：(a) 把這個 cut 改成延續 world 的連續運鏡（同一台攝影機，不要剪），或 (b) 給 begin-the 完全不同的取景：spark 特寫（spark 佔畫面高度 35%，偏左三分線 x≈640），右側留給預測面板。

## 章節層級

1. **能量曲線倒過來了**：intro 是鼓＋貝斯、低→中，應該一路累積到小節 8 交給 inst1（合成器整層進來）。實際的視覺密度是：低（power）→ 中（shield）→ 高（protection）→ 中高（pieces）→ **最高**（begin 整面牆）→ 低（object 開頭）→ 中（params）→ 高（init）→ **最低**（world、begin-the、simulation 共 ~3.7 s）。最後兩小節是最空的畫面，對不上音樂的上升。修法：begin 的牆降密度（見 05），world/begin-the/simulation 透過「把前面造出的東西放進世界」＋可見的灰塵＋真正的升降鏡頭把密度往上推，讓 simulation 成為本章最滿的一刻。

2. **構造一個接一個被丟掉，沒有累積**：電源種子 → 殼 → 棋盤 → 牆 → 方框 → 高度場 → 空地板，每個鏡頭的構造到下一鏡就消失（只有 shield→protection、object→params 延續）。分鏡的敘事是「被創造」，應該是一層一層組裝起來的。最低限度：(a) 殼的粒子真的變成棋子（pieces 的 points 轉場在接觸印樣裡看不出來，start 幀仍是完整的殼）；(b) 牆的 token 塌縮成方框的邊（object）；(c) world 把殼、方框、高度場以小尺寸放到地板上。

3. **色彩語義的漏洞**：分鏡規定藍色在「your pieces」第一次出現，但 PROTECTION（t≈3.5 s）的 BPE 切塊 `TION` 就是藍色、`EC` 是綠色；右下座標軸 gizmo 的 z 軸也從 shield 起就是藍色。建議：tokenChips 只用橘／灰；gizmo 三軸在 intro 內全部用 mid/faint gray（或只有 x 為橘），讓 pieces 的藍色游標成為真正的「第一次」。world 的同心圓用了玫瑰色調，也應改灰（玫瑰＝love）。

4. **轉場品質**：glide（power→shield）、xfade（object→params、init→world）運作良好。whip（pieces→begin）兩端的幀內容完全無法辨識，且有垂直接縫（見 05-5）；world→begin-the 的硬切是同場景跳接（見 10-1）。另外 spark 在相鄰鏡頭間大小跳動（90 → 240 px），建議 spark 的基礎尺寸由章節統一定義，只讓人聲能量在 ±25% 內呼吸。
